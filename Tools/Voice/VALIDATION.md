# 검증 결과 (2026-11-10)

Unity 6000.6.3f1, `KayKit_DepthSurvival` 씬에서 확인했습니다.

## 슬라이딩 윈도우 추가 후 재검증

- Unity 컴파일 오류 없음. 기존 BatchInference 검사 재실행 PASS(무음, 빠른 재입력, 채팅, 포커스, 권한 실패, 중복 콜백, Hold/Follow 회귀 포함).
- SlidingWindow 검사 PASS: 발화 중 요청, 중간 결과 미전송, 무음 종료 후 M 해제 전 최종 전달, 짧은 발화 결과 재사용, 동일 문장도 별도 발화면 각각 전달, 키 해제 후 중복 없음, 긴 발화 전체 최종 인식, 느린 서버 동시 요청 1개, 취소·모드 전환·STT 오류.
- 실제 실행 중인 로컬 Whisper 서버에 동일 한국어 합성 WAV를 실시간 속도로 재생. 두 모드 모두 `여기서 기다려줘.` 최종 텍스트를 기존 CpcTactics/LocalLlmClient 경로에 한 번씩 전달. SlidingWindow 첫 요청은 발화 종료 전, 최종 전달은 M 해제 전. 결과 `RealSttComparison.txt` 및 `Measurements/voice-recognition.csv`.
- 한 번의 측정: BatchInference 발화 종료→CPC 전달 4954ms/요청 1회, SlidingWindow 4595ms/요청 2회. 둘 다 전체 최종 인식을 사용. 합성 음성 1회이므로 일반적인 속도/정확도 결론을 내리지 않음.
- 실제 사용자 마이크, 소음 환경, Windows 권한 UI는 이번 자동 검증에서 사용하지 않음. 실제 Ollama로 최종 텍스트를 전달하는 경로는 확인했으나 모델의 모든 응답/전술 품질을 평가한 검사는 아님.

아래는 기존 배치 기능의 최초 검증 기록입니다. 당시 서버 미연결 기록은 과거 상태이며, 위의 새 검증에서는 실제 서버를 사용했습니다. M 해제 전 요청 0회 조건은 BatchInference에 해당합니다.

## 통과

- Unity 스크립트 컴파일: 오류 없음.
- 실제 InputSystem M 키 눌림/해제를 테스트용 가상 키보드로 주입.
- M을 누르는 동안 녹음 상태이며 STT 및 CPC 요청은 0회.
- M 해제 후 녹음기가 즉시 정지한 상태에서 최종 STT 결과 대기.
- 최종 콜백이 중복 호출되어도 공통 채팅 경로 전송은 1회.
- 무음, 빈 인식 결과, STT 실패, 마이크 권한 실패에서 전송 없음.
- 열린 채팅창에서 M을 입력하면 녹음 시작 없음.
- 창 포커스 상실 시 녹음 취소 및 장치 해제 호출.
- 인식 대기 중 다시 M을 누르면 이전 결과 폐기, 새 결과만 1회 전송.
- 컴포넌트 비활성화 시 녹음 정리. 씬 해제도 이 생명주기 정리를 사용함.
- 정상 JSON 응답을 기존 Unity 검증기로 전달하여 Hold 수락 후 플레이어 위치를 이동시켜도 CPC가 6.5초 이상 같은 위치에서 정지함.
- 상태 질문 처리 중 잘못된 follow 응답을 주입해도 Hold 유지.
- Follow 수락 후 NavMeshAgent 이동 재개.
- 저체력 긴급 후퇴에서 Hold 해제.
- WAV PCM16 / 모노 / 16kHz 헤더, 1초 데이터 길이 32044바이트.
- “지금 뭐 하고 있어?”는 상태 질문으로, “따라와”는 이동 요청으로 분류됨.
- 최종 플레이 검증에서 Unity Console 오류 0개. 기존 GPUResidentDrawer 렌더 설정 경고는 남아 있음.
- `Start-LocalStt.ps1` PowerShell 구문 검사 통과.

검사는 `Tools/CPC/Run Voice Feature Checks (Play Mode)`로 재실행할 수 있습니다. 실행 로그는 `Temp/CpcVoiceFeatureChecks.txt`에 생성됩니다. Unity 프레임이 1에서 1707로 진행된 상태에서 통과 결과를 확인했습니다.

## 검증 범위의 한계

입력 경계 검사는 실제 마이크를 녹음하지 않고 주입한 녹음기/인식기를 사용했습니다. 행동 검사는 모델이 반환하는 형태의 JSON을 실제 CpcTactics 검증기에 주입했습니다. 따라서 실제 마이크 인식 정확도, 실제 Windows 권한 거부 UI, 실제 Ollama의 한국어 명령 선택 성공률을 검증한 것은 아닙니다.

현재 로컬 접속 검사에서 `127.0.0.1:8080` STT와 `127.0.0.1:11434` Ollama는 연결을 거부했습니다. 서버/모델을 설치하거나 실행하지 않았습니다. 실제 음성 → STT → Ollama → CPC 전체 경로는 README의 설치 후 수동 절차로 확인해야 합니다.

대기 검증 과정에서 이 Unity 버전의 `NavMeshAgent.ResetPath()`가 `isStopped`를 false로 되돌리는 동작을 확인했습니다. 경로 초기화 후 정지하도록 순서를 수정한 뒤 6.5초 대기 검사를 통과했습니다.
