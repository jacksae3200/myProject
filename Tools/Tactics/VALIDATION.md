# 검증 결과 — 2026-11-10

**후속 정책 변경:** 현재 기본 Follow는 ‘따라오며 보호’이며 전투 대상을 생략하면 자동 선택합니다. 아래 과거 검사에서 사용한 ‘여러 후보면 되묻기’ 정책은 대체되었습니다. 최신 검증은 [FollowProtectionUnity.txt](FollowProtectionUnity.txt)와 [FollowProtectionModel.txt](FollowProtectionModel.txt)에 있습니다. 추종 중 교전/복귀, 적 사망 후 추종, 특수 위협 우선, 가까운 대상/유형 필터, 비전투 추종과 Hold 유지 검사를 통과했습니다. 실제 gemma4:12b에서도 Hold→Follow, Follow 유지 중 자율 Intercept, 모호한 전투 요청의 자동 대상 선택을 통과했습니다.

Unity 6000.6.3f1 / URP, `KayKit_TacticsTest`에서 플레이 모드로 검사했습니다. 연결은 원래 `KayKit_DepthSurvival`에도 저장했습니다. 실행 파일과 모델 설정 에셋의 모델명은 변경하지 않았습니다.

## 실제 로컬 모델

기존 Ollama `http://127.0.0.1:11434/api/chat`, **gemma4:12b**에 실제 요청하여 다음 경로를 확인했습니다. 응답 주입으로 대체한 검사가 아닙니다.

| 관측/기존 채팅 UI 입력 | 실제 모델 선택 | Unity 결과 |
|---|---|---|
| Spitter의 실제 Aiming 단계 | intercept | 이동/방패 실행 |
| 버로우의 실제 출현 흔적과 Emerging 단계 | evade | NavMesh 회피 실행 |
| Crawler의 실제 공격 후 Recovering 단계 | counterattack | 기존 근접 공격 실행 |
| 여기서 기다려 줘 | hold | 6.5초 이상 대기 |
| 지금 뭐 하고 있어? | question / none | 동일한 대기 지시 유지 |
| 이제 다시 따라와 | follow | 대기를 대체하고 추적 재개 |
| 저기 침 뱉는 놈부터 잡아 | attack + Spitter ID | 지정 대상 공격 실행 |
| 내 앞에서 침 좀 막아줘 | intercept + Spitter ID | 지정 투사체 위협 대응 |
| 어떤 놈이 제일 위험해? | question / none | 설명하고 기존 지시 자체를 유지 |
| 지목 단서 없이 두 후보에게 “저놈부터 잡아” | clarify / none | “어떤 놈을 먼저 처리할까?”로 되물음 |
| 기어오는 놈 좀 떼어줘 | attack/taunt 중 선택 | Crawler 대상 행동 선택 |

실제 모델의 정확한 대사, 제안/수락/실행 및 Ollama 토큰 지표는 [RealModelChecks.txt](RealModelChecks.txt)에 있습니다. 질문 검사는 행동 종류만 비교하지 않고 새 지시가 수락되지 않았는지도 확인했습니다. 모호한 대상 검사는 직전 대화로 지목 대상이 이미 정해진 경우와 구분하기 위해 대화 이력을 비운 독립 상황에서 실시했습니다.

이 모델 검사는 모델 지연과 실행 경로를 분리하기 위해 **테스트 실행 중에만 예고/회복 시간을 150초로 늘리고 기본 자율 폴백을 껐습니다.** 실제 게임/저장된 프리팹의 시간을 이렇게 바꾸지 않았습니다. 짧은 기본 예고 안에 LLM이 항상 응답한다는 의미가 아닙니다.

## Unity 결정적 검사와 회귀

[UnityChecks.txt](UnityChecks.txt)는 모델 형태의 JSON을 기존 검증기에 주입하되 실제 Input UI 경로, NavMesh 이동, 물리 트리거/투사체와 체력 판정을 사용한 검사입니다.

- 대기/추적 전환과 6.5초 대기.
- 물리 투사체가 CPC 방패 트리거에 충돌하여 소모되고 피해 20이 4로 감소함.
- counterattack이 기존 근접 타이밍/피해를 사용함.
- 기존 도발이 좀비 대상을 CPC로 바꿈.
- 숨은 버로우는 관측 목록에 없고 실제 출현 예고 뒤에는 본체가 아닌 흔적 위치만 관측됨.
- NavMesh 회피, 짧은 .8초 예고에서 LLM을 기다리지 않는 안전 대응과 별도 출처 로그.
- 저체력 후퇴 중 플레이어 지시를 보존하고 회복 후 재개함.
- 잘못된 JSON, 만료된 응답, 공격 단계가 바뀐 응답, 사망한 대상과 이동 불가 상태를 거절함.
- 동일 위협 신호를 반복 전달해도 모델 요청이 늘지 않음.
- NavMesh 밖의 먼 목적지(10000, 0, 10000)를 직접 경로 검증기에 넣어 도달 불가로 거절함.
- 접속 실패를 의도적으로 발생시켜도 프레임이 진행되고 대기 지시가 유지됨.
- 프로젝트 전체 스크립트 컴파일 통과. 검증 플레이에서 Console 실행 오류 0개.
- 기존 음성/채팅 회귀 검사도 재실행하여 M 눌림/해제, 최종 결과 1회 전송, 무음/권한/인식 실패 차단, 채팅 M, 포커스 취소, 빠른 재입력과 대기/추종을 통과함. 이 회귀 검사는 가상 녹음기/인식기를 사용하며 실제 STT 정확도 검사는 아님.

## 환경과 미확인 범위

처음 실제 추론을 시도했을 때 Ollama가 HTTP 500/CUDA 초기화 오류를 반환했습니다. 이후 같은 모델로 실제 추론이 정상 진행되어 위 검사를 통과했습니다. GPU 오류에 대한 동일 모델 CPU 1회 재시도 코드를 추가했지만 최종 정상 추론에서 그 오류 분기를 강제로 재현하지는 않았습니다.

여러 적/투사체가 동시에 몰리는 대규모 장시간 전투, 모든 맵의 복층/끊긴 NavMesh 조합, 모든 자연어 변형과 마이크→STT 인식 정확도는 이 전술 검사에서 확인하지 않았습니다. 기존 GPUResidentDrawer 렌더 설정 경고는 남아 있으며 이번 전술 변경에 포함하지 않았습니다.

재실행 메뉴와 테스트 씬 설명은 [README.md](README.md)에 있습니다. 플레이 화면은 `Assets/Tools/Tactics/TacticsPlay.png`에 저장했습니다.

## 군집 보호 후속 검증

[군집 보호 검사](CrowdProtectionChecks.txt)를 통과했습니다. 테스트 중 실제로 Normal 좀비 3개를 생성했습니다. 2개에서는 발동하지 않고, 3개에서 CPC가 NavMesh로 플레이어 곁으로 이동해 적 방향으로 방어했습니다. 실제 좀비 AI의 플레이어 대상 근접 공격에서 플레이어 피해 0, CPC 피해 2(원래 10)를 확인했습니다. 저체력 후퇴 우선/회복 후 재개, NavMesh 상실 정리, 군집 해소 후 원래 Hold 위치 복귀, 벽 뒤 적 미감지, 도달 불가 위치 거절도 통과했습니다. Console 실행 오류는 없었습니다. 이 검사는 즉시 Unity 안전 행동을 검증하며 새 protectplayer 선택에 대한 실제 LLM 추론 검사는 아닙니다.
